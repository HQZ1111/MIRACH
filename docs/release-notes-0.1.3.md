# Mirach 0.1.3

这一版几乎全在**悬浮窗（HUD）**和**插件兼容性**上。

## HUD 悬浮窗：从"打不开"到和 hermes 一致

- **修掉"打不开 / 一片空白"的根因**（三个独立问题）：
  - 运行期新建的 webview 必须继承主窗的 WebView2 启动参数。WebView2 的环境在同一用户数据
    目录下是进程级单例、只认第一次那套选项，选项不一致就直接失败
    （`HRESULT 0x8007139F`）；而 Tauri 的 `WebviewWindowBuilder::build()` 走 AppHandle 是
    "发完即返回"，失败只写日志 → 窗口在注册表里、句柄永远拿不到。**内置浏览器、HUD、会话小窗
    全被这一个问题打掉**，现在都正常（已实测：HUD 与内置浏览器都能真的加载页面）。
  - HUD 里那 741 行皮肤是 hermes 原样搬来的，写的是 hermes 自己的主题 token
    （`--dt-card` 等），mirach 用的是官方 `--dsw-alias-*` → 每个 `var()` 都解析成空值，
    输入条整条透明。加了 token 桥。
  - 一条"dock 里只留 composer-root"的规则把输入卡片整条 `display:none` 了
    （mirach 的 dock/root 映射落到同一元素）—— 修掉映射。
- **形状与行为对齐 hermes**：窗口 620×320、屏幕底部居中（离下沿 72px）；
  输入条在上、对话区挂在下面并可在空闲时折叠；**没有标题栏**（退出与方向切换收成一小簇
  悬浮控件，钉在条子的另一端，鼠标进入才现身）。
- **输入条显示完整**：官方 root 只有 28px、卡片 44px，之前顶部被裁 13px；现在条子给足高度。
- **输入条上/下可切换**（用户要求）：按钮一键把输入条与对话区对调，选择本地记住。
- **打开 HUD 时主窗自动让位**（hermes 语义 "the HUD IS the surface now"）：关掉 HUD 后主窗
  自动回来。两条路径都实测过（关窗按钮、Alt+F4/系统关闭）。
- 多窗口共存：主窗与 HUD 各自连内核，不再互相把对方的流踢掉（此前两边刷屏互抢，
  HUD 永远"引擎未连接"）。

## 插件：dsh 升级后"对不上"不再把应用装死

- **激活前试跑**：写进 profile bundles 之前先真的 `import()` 一次插件入口，插件与当前引擎
  不兼容（例如引用了引擎已删除的导出）当场拦住 → 安装事务回滚、不写 bundles。
- **last-good 快照 + 自动回滚**：引擎启动成功后记录一份"能用的 bundles"；启动失败且清单变了
  就自动回滚并报出是哪个插件干的。
- 通讯图标接了社区 **`dsh-im`**（统一 IM 桥：会话映射 / 通知总线 / 审批流），面板改成读引擎
  真状态并可一键装渠道适配器（微信/企业微信/飞书/Telegram），不再是本地假清单。

## 顶栏插件

- 图标改成**插件名缩写 + 每个插件稳定的配色**（实测 7 个不重样，未激活半透明），
  点图标直接打开该插件自己的面板（有独立页面就开页面，否则打开插件管理器并定位到它）。

## 说明

- 自更新端点不变：`docs/latest.json`（Gitee raw），带签名校验。
- 首次启动仍需应用内安装依赖（Node + 引擎 + 桥接，约 200–300MB）；安装包内含离线运行时，
  无需另外下载便携包。
